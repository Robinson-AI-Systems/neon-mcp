## Full integration and acceptance

- `neon_dev_checkpoint`: full-owner, exact scoped connection and one active recorded
  non-production, nonprotected, unshared, expiring V-1 run branch; trusted pg
  `pg_current_wal_lsn()` bounded read; persist immutable checkpoint LSN under
  run/project/branch/owner/name with a unique constraint; independent service DB
  readback, no raw credentials, durable B-1 idempotency.
- `neon_dev_reset_branch`: same V-1 checks, verified parent and complete branch
  inventory with no unowned descendants. Preview and confirm; call the existing
  priced B-1/B-4/D-2 reset operation without bypassing preservation. A named backup
  must be observed, registered in the same run, given an expiry and read back.
  Ambiguous responses remain pending and are never automatically reissued.
- `neon_dev_restore_checkpoint`: persisted exact branch/run/name lookup and
  project history-retention window check. Use only the stored LSN (never caller
  supplied). Restore itself with D-2 preservation + pricing; verify and register
  the preserved branch and expiry, or return pending with recovery evidence.
  Do not touch protected, production, app-owned or child-bearing targets.
- `neon_dev_migration_preview`: exact run-owned parent checked; owner submits
  bounded classified SQL or public HTTPS raw SQL migration files. The latter
  compare ordered names against current `_prisma_migrations`, refuse unresolved
  failures/out-of-order history, apply pending statements in order. Two-fetch
  drift checksum, strict AST roots, no unknown SQL and independent table-size
  lock warnings. Run exclusively through B-3c expiring disposable child and
  B-4 pricing gate; reflect per-statement affected counts and schema-change
  evidence. `keep: false` deletes the child and confirms cleanup; `keep: true`
  retains only one independently verified one-hour child recorded in V-1's
  run/cleanup ledger. Never writes the parent. Fail closed on unknown cost,
  unsafe SQL, drift, or lost response; no production activation.
- Real PostgreSQL test: immutable checkpoint with denied cross-owner lookup and
  expired-run, `_prisma_migrations` pending/failed mapping, lock warning for
  large tables, isolated migration fixture and unchanged source table. Fake
  Neon/unit: B-1 preview/confirm/no replay, restored source equals stored LSN,
  parent never targeted by preview SQL, retention and preservation/expiry.
- Publication: exact PR-head `check`/`unit`/`db`/`ci`/
  `release-policy`, self-review, all review threads resolved, main CI.
  Custom hosted direct-MCP, provider read/write, actual restoration, retained
  child and cleanup require owner-approved scratch run **after release**.
  Such external acceptance is not shown by standard connector reads.
