# V-1 — Run-owned development branches and precise cleanup

Status: IN_PROGRESS (implementation PR #160). Approved scope:
\`docs/designs/BATCH-V.md\` §4 V-1 and owner decisions IN-10/IN-12.
Baseline: merged main #159; production/live unchanged.

## Contract and drift review
- Reuse B-1 durable mutation audit, B-4 verified provider plan and persisted dollar caps,
  B-2 exact protected and production classification, project-key routing and Neon SDK.
- Existing \`neon_branch_create\` cannot be simply called as a nested write: it owns
  its own B-1 reservation and lacks run persistence/annotation/mandatory expiry.
  V-1 instead uses the same reviewed SDK operation, request and spend primitives.
- V-1 records runs and exact created branches in separate service-owned SQL tables;
  Git/provider annotations are recovery *hints*, never deletion authorization.
- Provider request: \`createProjectBranch\` POST /projects/{project_id}/branches with
  top-level \`annotation_value.rtc_run\`, strict expires_at, unprotected branch,
  inherited data/schema-only source, small read-write compute. Verify payload through
  vendored-schema-aware fake and independent provider reads.
- No real key, real provider mutation, independent live acceptance, production
  activation, spend authorization, manual release or inter-repository modification.

## User outcome
Select an enrolled project and parent, name a run-owned branch, preview verified
monthly branch + compute cost and expiration, explicitly confirm within durable
owner spending caps, then list its run and clean *only* the owned development
branches. Cleanup reads the exact persisted run/object set, reclassifies every
provider branch as nonproduction/unprotected/unshared and refuses any unknown
child, stale/incomplete provider list or changed app ownership. Children are
soft-deleted first; expired branches are recognized from a full provider list.
Only independent absence marks a row cleaned. Lost/ambiguous writes remain
pending and are never replayed or inferred from an annotation.
