## Contract
- `src/neon/sql.js`: `withSqlClient(ctx, {projectId,branchId,database,role,pooled}, fn)`.
  Must fetch Neon connection URI via guarded client with requested branch, endpoint, database, role and pooled flag.
  Explicitly refuse URI host matching `DATABASE_URL` host (also lowercasing), even for preview and same DB name.
  URI stays in request memory only, no result, log, error, change log or tool metadata; sanitize thrown messages.
- Set session statement timeout (15s) and lock timeout (5s); always release connection in `finally`,
  even for rejected queries. Do not expose the URI to callback or tools.
- `test/helpers/sql-client.js` injected pg.Pool factory for throwaway localhost testing (never remote).
- Tests: fake Neon URI call checked against pinned API schema, same-host refused before opening pool,
  errors scrubbed, release on failure, real disposable-Postgres query and isolation. No live Neon account.
- Security review AI-PR-READ-FIRST #5–11, #17. No direct SQL tools until Batch B/D guards.
- Done: unit and DB tests, lint, `npm run check`, exact-head aggregate `ci` green; update STATUS,
  ARCHITECTURE, work index, successor A-7 deployment card. No live provisioning or paid action.
