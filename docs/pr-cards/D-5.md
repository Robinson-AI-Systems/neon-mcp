## #127 — scoped read-only SQL diagnostics

`neon_sql_explain` accepts only an AST-proven SELECT, defaults to nonexecuting EXPLAIN, and permits ANALYZE only when explicitly requested for that read-only SELECT. Central B-3 SQL admission, transaction, owner policy, direct verified connection and bounded result shaping still apply. `neon_sql_list_activity` executes a fixed current-database-only query returning session/lock/wait metadata but not raw SQL text or cancellation authority. Both require exact independent project/branch/endpoint/database/role provider verification and do not expose role deletion.

Coverage: fake provider identity GETs, real PostgreSQL-parser classification, default/explained execution, prohibited modification plans, fixed current-database activity, existing policy refusals and registry parity. Exact-head CI, deployment and actual provider SQL behavior remain distinct.

## #130 — owner-confirmed single-query cancellation

`neon_sql_stop_query` is a B-1 owner-full audited, disruptive operation. It requires the exact enrolled project, verified branch, direct compute endpoint, database and role, and one positive PostgreSQL PID. Preview discloses the application interruption; a separately submitted `confirm:true` and a durable request key are required. The normal protected-resource, app-ownership and production-operation safeguards run before any SQL, and the operation refuses an idle or disabled compute to avoid waking it automatically.

The only privileged SQL is fixed inside `src/neon/sql-run.js`: select a *currently active* same-database, same-current-user client backend by bound PID (not the tool's own backend), record backend/query start fingerprints, then use `pg_cancel_backend` for that exact still-observed process. Never use `pg_terminate_backend`, arbitrary caller SQL, pooler administration, or a cross-database PID. A fresh separately bound direct SQL connection checks the original active query ended before reporting success. Timezone-independent epoch fingerprints avoid mismatched formatting; ambiguous outcomes stay unconfirmed and a duplicate audited request is not replayed.

Provider-identity and B-1 lifecycle fixtures, fixed-SQL binding/identity tests, idle/scope/production/owner denials, POST-free fake Neon reads and independent confirmation regressions accompany source. No actual owner's running query was canceled or touched. A real isolated owner-approved scratch branch and a checked deployed revision are needed to close provider acceptance. This cancellation tool is unrelated to—and does not resolve—the unobservable D-4 PgBouncer idle-client precondition for deleting roles.
