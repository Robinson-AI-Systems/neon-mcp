## #127 — scoped read-only SQL diagnostics

`neon_sql_explain` accepts only an AST-proven SELECT, defaults to nonexecuting EXPLAIN, and permits ANALYZE only when explicitly requested for that read-only SELECT. Central B-3 SQL admission, transaction, owner policy, direct verified connection and bounded result shaping still apply. `neon_sql_list_activity` executes a fixed current-database-only query returning session/lock/wait metadata but not raw SQL text or cancellation authority. Both require exact independent project/branch/endpoint/database/role provider verification and do not expose role deletion.

Coverage: fake provider identity GETs, real PostgreSQL-parser classification, default/explained execution, prohibited modification plans, fixed current-database activity, existing policy refusals and registry parity. Exact-head CI, deployment and actual provider SQL behavior remain distinct.
