## A-5a — Encrypted key persistence and validated narrow-key selection

- `src/core/crypto.js` contract-generic authenticated AES-256-GCM encrypt/decrypt using
  `TOKEN_ENCRYPTION_KEY` from environment, never stored or printed, with clear missing-config error.
- `src/db.js`: organization metadata, active key save/read/list and revoke; only encrypted key contents;
  partial unique scope enforced; reject kind mismatch, guard same-org isolation.
- `src/neon/keys.js`: no plaintext in returned summaries, one key kind per project, prefer scoped project key,
  fallback org key only when authorized; never accept `admin` kind. Verify candidate key by `GET /auth`
  and scope probe through the approved Neon client with durable per-key budget, no live calls in tests.
- Tests: fake Neon API authorization/reach, AES-GCM tamper/wrong key, narrowest-key selection and isolated
  Postgres duplicate/revocation cases. No key arguments on MCP tools.

## A-5b — One-time outbound and inbound secrets

- `src/core/one-time.js`: ciphertext-only, outbound secrets consumed at most once within ten minutes;
  inbound requests are created without plaintext, owner supplies secret through authenticated setup route,
  consumer atomically takes and deletes it once. Bound to org, no secret in logs, change log or tool results.
- `src/db.js` SQL plus in-memory fake methods, database expiry/single-use tests. No public retrieval without passphrase.
- Preserve `one_time_secrets` / `secret_requests` table contract; never commit live keys or URIs.

## A-5c — Secure setup page and initial read-only tools

- `api/neon/setup.js` for passphrase-protected key entry, validation, revoke, secret exchange and viewing;
  serverless preview never permits production activation or org-only privileged operations.
- Read tools `neon_whoami`, `neon_list_accounts` (no plaintext; scope-safe), registered only when
  defensible read-only handlers exist; update TOOL-CATALOG and write contract.
- Integrate organization dropdown, accessible project scopes only from verified stored keys,
  and safe server error handling. No unapproved live Neon/Vercel provisioning.
- Tests: wrong passphrases locked after five attempts, CSRF protection, one-time secrets, metadata,
  token and org scoping, no key or connection URI in any tool result.
