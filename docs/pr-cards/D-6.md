## #143 — Schema inventory and table inspector

Deliver `neon_schema_list_schemas`, `neon_schema_list_tables`,
`neon_schema_describe_table`, `neon_schema_list_extensions` as real
read-only bounded PG catalog tools. Require exact independently verified
project/branch/endpoint/database/role and direct host before B-3
read-only transaction. Never interpolate caller schema/table names;
bind PostgreSQL identifiers as $1/$2. No table records or default
literals/policy expressions are read; only column, index,
constraint, RLS policy metadata, sizes and estimates.

Every query limits 201; B-3 owner maxRows of 200 detects truncated
incomplete results. The table inspector independently fetches and
correlates columns, indexes, constraints and policies. Never claim
complete coverage if one subquery fails or truncates. PostgreSQL 17
disposable tests prove schemas, RLS, indexes, constraint and bound
hostile identifier nonexecution. Provider trust and production gates
remain. No live SQL data or mutation was accessed.

Remaining D-6: table DDL, name search, object inventory,
type generation, extension enable/disable, index DDL,
health check/index suggestions/vacuum, index reindex D-9.
Complete cohesive end-user workflows with real tests and a checked
deployment; do not pad PR cadence.

## #144 — cross-schema search and object listing

New registered `neon_schema_search` returns matching relation and
column names without loading application rows. One fixed UNION read
accepts bound term and optional schema; never concatenates caller SQL.
`neon_schema_list_objects` enumerates eight real PostgreSQL object
families through kind-selected constant queries and optional bound
schema; database-wide publications explicitly refuse a schema filter.
Both use provider-verified five-ID and direct host B-3 read policy and
201-row bounded catalog with incomplete result reporting. Real
PostgreSQL disposable tests create and rediscover a view, enum,
function, sequence, RLS policy, plus hostile injected search text.
No claim of custom live-service SQL acceptance or schema mutation.

## #145 — bounded PostgreSQL health report

Implement `neon_health_check` over fifteen constant AST-proven
`SELECT` statements; defaults cover size, cache, connection counts,
database XID age and invalid indexes. Additional options inspect
sessions/locks/waits, long-running sessions without SQL query text,
dead tuples, autovacuum, unscanned or structurally duplicate indexes
as candidates only, replication slots, table size and scan statistics.
Each statement has `LIMIT 201`, runs under the same exact verified
direct five-resource connection, read-only transaction and owner
maximum 200 rows. Provider SQL errors and truncation are explicit
unknown/incomplete per individual check; do not claim a healthy
database, a proven duplicate index or successful vacuum from stats.
Tests use actual disposable PostgreSQL 17 to read size, XID, table
size, connections, locks and cache plus unit injection with
wrong provider identity and permission denied. No writes, cost
increase, production enablement or manual release authorized.

## #146 — TypeScript and Zod row types from verified catalog metadata

The D-6 `neon_schema_generate_types` workflow accepts exact
database + non-system schema, optional selection of up to 20 distinct
table names and format `typescript` or `zod`. The reviewed
TABLES_SQL and COLUMNS_SQL under B-3 return table/column names,
PostgreSQL formatted data types and nullability. Caller choices are
always parameters, not SQL identifiers. Complete bounded catalog
coverage and unique noncolliding generated model names are mandatory
before publishing generated code. JSON-facing scalar choices are
conservative, with numeric/bigint/date-time represented as strings
and ambiguous enum/domain/bytea types `unknown`. No application rows,
default expressions, policy bodies, live migrations or credentials
are returned. Real Postgres tests compile-check parsable TypeScript
using Node 24's built-in type stripping and inspect nullable Zod
schemas; secret scan and B-3/production policies still apply.
Unverified custom live acceptance remains separately open.
