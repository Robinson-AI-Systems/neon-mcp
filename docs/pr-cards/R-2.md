## Full acceptance (do not mark R-2 complete until all pass)
1. Public RTC 2 manifest has correct server, prefix neon_, actual counts, scope and listing/result dialect, serving version and independently established deployment revision, and clear health/auth/connection metadata; preserve RTC 1 until the cutover passes.
2. Every authenticated HTTPS tool/list/describe/call/batch/whoami/result route uses one exact pass principal, denies native OAuth tokens, preserves effective profile/tenant and B-1/B-2/B-4 write guards, and produces RTC 2 error envelopes.
3. Bounded cursor discovery and 1-based byte-exact 24-hour content-page recovery obey 8192-byte reply limits, exact grant binding, expiration and rejection of foreign or malformed cursors/handles.
4. Pass rate limits are atomic across two server instances, enforce configurable per-pass caps and Retry-After; revoked/expired tokens refuse on the next call.
5. Valid OpenAPI describes no more than 30 supported operations; public client and confidential PKCE/resource flows remain accurate, and server identity is independent of Host spoofing.
6. Agent-visible release version and SHA agree across actual running MCP initialize, authenticated neon_whoami, public manifest, health and front door, with honest unknown SHA handling and safe update instructions.
7. One normal customer OAuth sign-in and independent backend-only developer grants: mobile public handoff migrates without breakage or misleading developer branding; dev privileges never come from customer tokens.
8. Fake-provider, actual disposable PostgreSQL, two-tenant, deny/replay, direct-client, post-release and source-vs-live acceptance pass. No Hub live connection is required.
