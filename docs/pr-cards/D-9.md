## Migration history — PR #149

Deliver `neon_schema_list_migrations` over actual app migration tracking
metadata for Prisma, Drizzle, Knex, Flyway and golang-migrate. First read a
fixed bounded PostgreSQL catalog with optional bound schema; only observed
recognized table and column sets may select one of five fixed read layouts.
Dynamically quoted schema names must originate in verified bounded catalog
metadata and pass strict non-system identifier validation. Never fetch raw
migration SQL, execution logs or application rows. Read-only transactions,
owner max rows, exact five-part provider target and direct host apply to each
query. Unknown or truncated states fail closed. Repeated Prisma attempts are retained;
only successfully applied names satisfy expected-history checks. Shared
`src/neon/sql-ident.js` quotes catalog identifiers. Failed Prisma migrations
include non-mutating guidance to inspect and resolve via the app's own workflow.

Real throwaway PostgreSQL fixture covers complete Prisma/Knex metadata,
failed migration classification and preserved records. Unit tests cover

## PR #153 — bounded branch data comparison
Baseline main: merged #151/#152. Reuse exact five-part provider identity,
B-3 read-only admission, catalog SQL, central quoteIdent and result handles.
Compare one-to-five regular tables on two verified distinct targets. Require
matching observed columns and keys; count first, cap each table at caller
rowLimit (default 50,000), page only 100 MD5 key/row fingerprints at a time.
Report added/removed/changed counts for PK tables; unkeyed tables get count
and sorted row-checksum comparison. Oversized tables and schema mismatch
are explicit incomplete results. Recheck counts/checksums after pages; any
observed drift, partial read or collision fails closed. No raw values, keys
or fingerprints in output. Separate transactions and MD5 limitations are
explicit, never claim an atomic snapshot or cryptographic equality proof.
Point-in-time provisioning remains separate owner/spend-gated work.
C-2 budget correction measures the approved everyday wire catalog, while
still checking every tool description/schema and existing 5k/20k/1.5k caps.
Meaningful unit and disposable two-database PostgreSQL tests cover actual
changes, unkeyed duplicates, identity/partial/drift refusal and no mutation.
Custom live acceptance remains in STATUS release-follow-up queue.


## #157 — confirmed development concurrent reindex (code acceptance pending)
Rebuild a single valid ready index or all verified indexes of one regular,
non-system development table using PostgreSQL REINDEX INDEX/TABLE CONCURRENTLY.
Owner-only B-1 preview/confirmation, exact direct provider identity and complete
bounded table/index inventories are required before and after DDL; production,
protected and app-owned targets are refused freshly before mutation. Index
OID/size/scan drift is expected after a successful rebuild, but logical
index identity and valid/ready state must match independent readback.
No transaction, automatic retry, invalid _ccnew cleanup or production override.
Stored sql.maintenance_timeout_ms defaults to 600000 (ten minutes),
with 15000 minimum and 3600000 maximum; owners may only tighten it.
PostgreSQL exclusion indexes are refused before reservation because
REINDEX CONCURRENTLY skips them. Ambiguous outcomes use a separate
read-only recovery inventory including invalid _ccnew/_ccold artifacts;
never claim mutation success or perform automatic cleanup.
Local/disposable-Postgres, all-door write contracts, exact-head CI and future
custom hosted acceptance are distinct evidence layers.
