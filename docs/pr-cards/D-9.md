## Migration history — PR #149

Deliver `neon_schema_list_migrations` over actual app migration tracking
metadata for Prisma, Drizzle, Knex, Flyway and golang-migrate. First read a
fixed bounded PostgreSQL catalog with optional bound schema; only observed
recognized table and column sets may select one of five fixed read layouts.
Dynamically quoted schema names must originate in verified bounded catalog
metadata and pass strict non-system identifier validation. Never fetch raw
migration SQL, execution logs or application rows. Read-only transactions,
owner max rows, exact five-part provider target and direct host apply to each
query. Unknown or truncated states fail closed. Repeated Prisma attempts are retained;
only successfully applied names satisfy expected-history checks. Shared
`src/neon/sql-ident.js` quotes catalog identifiers. Failed Prisma migrations
include non-mutating guidance to inspect and resolve via the app's own workflow.

Real throwaway PostgreSQL fixture covers complete Prisma/Knex metadata,
failed migration classification and preserved records. Unit tests cover

expected names. No SQL write, plan purchase, provider mutation or live
