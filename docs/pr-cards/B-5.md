1. **Proposed** `src/neon/errors.js` exports `formatNeonError(error,{needKey})` and `formatSqlError(error)`. Inputs: status/code + request ID + safe optional problem details; output: `{code,status?,message,cause,action,technical,retryableRead?}`. No raw errors returned, errors not persisted. Unknown messages sanitized.
2. HTTP 401/403/404/409/423/422/429; plan-limit and branch-with-children patterns; required key kind originates from trusted handler metadata, not provider text. Technical line includes only safe request ID.
3. SQLSTATE 42P01,42703,42501,23505,23503,23502,25006,57014,55P03,53300,28P01,3D000,40001,40P01,08*; non-Postgres disconnect codes only trigger read-only retry.
4. Integrate `src/neon/client.js` safe status outputs with formatter, preserving `unknown_outcome` no-write-replay semantics. Integrate `sql-read.js` error return; **never automatically retry writes**, only one immediate reconnect of AST-proven read on first connection-reset.
5. New `tests/unit/neon-errors.test.js` covers each mapped code and redaction; client existing fake Neon and read runner regression; no external API/DB/secret.
