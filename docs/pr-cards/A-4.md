## A-4a — API wrapper and operation waiter (#10)

- `src/neon/client.js`: `makeNeonClient({ key, orgId, budget, fetch, baseUrl, sleep })`,
  `call(client, operationId, params, {write,requestKey,budgetMs})`,
  `requestKey(ctx,tool,args)`, `findExisting`, `listAll`.
- SDK retries disabled; mandatory injected `budget.consume()` for *every* request including retries/reconciliation.
  Only retry statuses 423/429; no blind retry after 500, timeout or network failure; a write requires a request key.
- `src/neon/operations.js`: `waitForOperations` bounded to 45 seconds, status check and pending continuation.
- Tests: `tests/unit/neon-client.test.js`, `tests/unit/operations.test.js`, existing fake-Neon contracts.
- No handlers exposed to users until subsequent security batches, no production access and no live Neon calls.

## A-4b — Durable counter and pinned-spec tooling (next)

- Add `src/db.js` atomic rate counter on `rate_limits` by key/minute; `src/neon/budget.js` adaptive client
  budget (default 500 requests/min across all instances, upper bound < Neon's 700/min ceiling).
  Fail closed on database error, one counter per key/scope, expire window safely without leaking key IDs.
- `src/neon/openapi-index.js` pure operation index; `scripts/openapi-find.mjs` bounded method/path/opId lookup;
  `scripts/neon-api-drift.mjs` compare pinned and live spec when reachable, report additions/removals safely.
  Move YAML parsing to runtime dependencies only if actually needed there; prefer a pure index and script-only YAML.
- Unit and disposable Postgres tests: two independent clients consume 500 allowed, call 501 refused;
  budget counters count retries and operation polls; offline lookup tests; drift tool never alters pinned YAML.
  Real Neon key is unnecessary and prohibited.
