- `neon_dev_list_scenarios` lists every table and its dependencies or renders a reproducible planning preview with exact row counts (five tables per scenario), three fabricated sample rows per table, and no SQL/database access. `generateDemoRows` yields the entire bounded dataset for future write implementation, with deterministic IDs, parent ID references, reserved `example.com` email domains and fictional 555-01xx telephone numbers.
- No schema changes, database writes, Neon API calls, spend requests, privileged owner action, real customer rows, or arbitrary web imports are introduced by this slice.
- Unit tests enforce four scenarios, deterministic seed, dependency order, exact column coverage and generated row counts, bounded validation, fake-only contact fields, and owner-agnostic discovery. Exact registry/profile/catalog source contracts are updated.
