## Build contract

- `src/db.js` (only file with this server's SQL):
  - `export const SCHEMA_TABLES` — exactly, in this order: `neon_orgs`, `neon_keys`, `oauth_clients`, `oauth_codes`,
    `oauth_tokens`, `login_attempts`, `rate_limits`, `change_log`, `one_time_secrets`, `secret_requests`, `settings`.
  - `export const CONNECTION_FIELDS = ['neon_org', 'project_scope', 'mode', 'profile', 'listing']` and
    `connectionSettings(row)` (A-3's refresh helper copies exactly these; A-3 adds the test that a new connection column
    must be listed here).
  - `export function createDb(sql = productionSql())` — `sql` is a tagged-template function (`@neondatabase/serverless`
    `neon(DATABASE_URL)` in production, created lazily; `neonShapedQuery()` in tests). Missing `DATABASE_URL` → the plain
    error "DATABASE_URL is not configured. Set it in the Vercel project (docs/DEPLOY.md)." at call time, never at import.
    Non-function `sql` → `TypeError`.
  - `db.initSchema()` — the §2 SQL verbatim: every `CREATE TABLE IF NOT EXISTS` / `CREATE [UNIQUE] INDEX IF NOT EXISTS`,
    including `neon_keys_one_per_scope` (partial unique, `WHERE revoked_at IS NULL`) and `change_log_request_key`; plus
    expiry indexes `oauth_codes (expires_at)`, `oauth_tokens (refresh_hash)`, `oauth_tokens (expires_at)`,
    `login_attempts (ip, attempted_at)`, `one_time_secrets (expires_at)`, `secret_requests (expires_at)`. No `DROP`,
    `TRUNCATE`, `ALTER … DROP`, no seed rows (settings defaults are seeded by B-2/B-3/B-4).
  - `export async function initSchema()` → `createDb().initSchema()`.
- `test/helpers/fake-db.js`: add `initSchema()` (records `SCHEMA_TABLES`) and `listTables()`; keep `put/get`.
- No tools, no API routes, no Neon API calls, no keys (A-5 writes `neon_keys` rows).

## Tests

- `tests/db/schema.test.js` (real Postgres, isolated schema):
  1. `initSchema()` creates exactly `SCHEMA_TABLES`; a second run changes nothing (same tables, same index list).
  2. `neon_keys`: a second non-revoked key for the same `(org_id, kind, project_id)` fails with SQLSTATE `23505`; after
     setting `revoked_at` on the first, a new one inserts; `kind = 'admin'` fails with `23514`; two `org` keys with
     `project_id` NULL collide (the `COALESCE` in the index).
  3. `oauth_tokens` / `oauth_codes` defaults: `mode = 'preview'`, `profile = 'everyday'`, `listing = 'catalog'`,
     `kind = 'connector'`; columns include `token_hash`, `refresh_hash`, `neon_org`, `project_scope`; no column named
     like `access_token`, `refresh_token`, `password`, `key_plain`, `plaintext`.
  4. `neon_orgs.production_enabled` defaults to `false`; `change_log` has `production`, `spend_month_cents`,
     `restore_lsn`, `operation_ids` (`text[]`), `request_key`, `confirmed`.
  5. Secrets are only ciphertext columns: `neon_keys.key_enc`, `one_time_secrets.ciphertext`, `secret_requests.ciphertext`.
- `tests/unit/schema.test.js`: fake `initSchema()` twice → `listTables()` equals `SCHEMA_TABLES`; `createDb('x')` throws
  `TypeError`; `createDb()` without `DATABASE_URL` throws the plain message when called; a static scan of `src/db.js`
  finds no `CREATE TABLE`/`CREATE INDEX` without `IF NOT EXISTS` and no `DROP`/`TRUNCATE`.
- Existing `tests/unit/db-contract.test.js` and `tests/db/contract.test.js` stay green.
